# Чтец Qwen — исправление JNI v0.3

**Фактическая причина NPE 17.11.2026 09:36:46:** Kotlin external для nativeSynthesizeStreaming имел лишний параметр iclPromptPath. Но в **реально собранном** C++ submodule 4562731dc612cb87b4cd1eedac275a17d1078773 отсутствует icl_prompt_path. Аргументы нативного вызова сместились, в т.ч. callback стал null. C++ немедленно возвращал null.

Исправлено: Kotlin сигнатура строго соответствует зафиксированному C++ ABI. В CI добавлена автоматическая сверка порядка/типов аргументов из pinned C++ и Kotlin, а не проверка одного имени JNI-символа. При null до первого аудиоблока код переключается на исходный (проверенный в Studio) nativeSynthesize, записывая звук через ту же callback-процедуру.

Сохранены: импорт PDF/TXT, 15-секундный тест, потоковая запись валидного WAV после каждого аудиоблока, отмена при следующем callback, частичный WAV, журнал и расчёт RTF. Не менялись C++ ядро и другие проекты. Как и ранее, физический запуск на телефоне ещё обязателен; CI не доказывает звуковое качество.

Новый packageId, поскольку старый APK был подписан недоступным временным debug-ключом. Для отдельного тестового приложения нужна повторная загрузка модели и новый голосовой профиль. **НЕ запускать пятиминутную генерацию до успешного короткого теста.**
